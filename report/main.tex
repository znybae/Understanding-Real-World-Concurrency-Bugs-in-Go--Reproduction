\begin{abstract}
We reproduce selected results from Tu et al.~\cite{tu2019go},
\emph{Understanding Real-World Concurrency Bugs in Go} (ASPLOS 2019).
We test three claims: that message passing accounts for a substantial share
of blocking bugs (C1), that Go's runtime deadlock detector finds only a
small fraction of blocking bugs (C2, Table~8), and that the data-race
detector finds only part of the non-blocking bugs (C3, Table~12).
Inside a pinned Ubuntu 18.04.6 and Go 1.10.8 container we reran six reduced
cases---Kubernetes \#5316, Docker \#24007, Docker \#25384 and Docker \#27037,
including two fixed variants---three times each. Every official check
matched its expected symptom (indicator mean $1.00 \pm 0.00$).
The selected mechanisms were reproduced, but the paper's aggregate
proportions remain inconclusive because we did not re-evaluate the original
benchmark. An extension that changes one factor at a time shows that the
Figure~8 loop-variable race disappears under the Go 1.22 language rule on
an otherwise identical Go 1.23.12 toolchain, while the three control bugs
still appear. Overall, the work is partially reproduced.
\end{abstract}

\section*{AI Usage Statement}
The group used an AI assistant (Grok Bot) to help implement the extension
runner and summarizer, draft and revise English report text (especially the
extension, deviation attribution, abstract, conclusion, and these
statements), organize experiment records, and troubleshoot the Git and
Overleaf workflow. Every quantitative result in the report was taken from
archived official logs and checked against those files. AI-generated
wording was reviewed by the corresponding authors before inclusion. No AI
tool was used to invent experimental numbers.
