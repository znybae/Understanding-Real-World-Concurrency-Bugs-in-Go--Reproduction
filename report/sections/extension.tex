\section{Extension}
\label{sec:extension}

\subsection{Question and Motivation}
Do the reproduced bugs behave the same way on a modern Go toolchain? Go 1.22 changed
the scope of \texttt{for}-loop variables from one variable per loop to one per
iteration, which removes the root cause of the closure race in Figure 8 (Docker
\#27037). We test whether this language change, and not a newer toolchain in general,
eliminates the race, while the other three bugs act as controls.

\subsection{Design}
We compare three configurations on the same Ubuntu 18.04 base image and the same
machine, with unchanged bug source files:
(A) Go 1.10.8 in GOPATH mode, the baseline;
(B) a modern Go toolchain with \texttt{go 1.21} in \texttt{go.mod} (old loop rule);
(C) the same toolchain with \texttt{go 1.22} (new loop rule).
A vs.\ B isolates the toolchain and runtime; B vs.\ C isolates the language rule.
Each case runs at least 10 times per configuration.
